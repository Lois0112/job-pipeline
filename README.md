# job-pipeline · 岗位日报生成器

把散在各处的校招岗位信息，压成一份**按方向分组、带原始投递入口**的日报表，每天自动发到邮箱。

找工作最耗时间的不是投递，是**筛**：同一个岗位在省市分公司、集团总部、学校就业网、招聘平台上各发一遍，字段还不一致。这个工具把「找」和「排」拆开——抓取端（人或 AI Agent）只产出结构化 JSON，剩下的校验、去重、过期过滤、分组、渲染全部交给代码，结果稳定、可复现。

## 效果

输入 `data/jobs.sample.json`（12 条，含 1 条重复），输出：

```
生成 11 条岗位（去重 1，过期 0）
  → out/2026-11-04.md      # Markdown，进 git、贴聊天
  → out/2026-11-04.html    # 邮件 HTML，表格不会散架
```

Markdown 片段（`out/2026-11-04.md` 实际内容）：

| 岗位名称 | 公司 | 城市 | 方向 | 投递截止 | 投递入口 |
|---|---|---|---|---|---|
| 信息通信业务岗（网络维护与服务支撑、网发建设） | 中国电信 湖南省公司 | 长沙 | 国企央企-通信 | 以省公司公告为准 | [投递页面](https://job.chinatelecom.com.cn/wt/TELE/web/) |
| 射频工程师 | 七十迈（70mai） | 上海 / 深圳 | 通信工程-射频 | 招满即止 | [投递页面](https://70mai.zhiye.com/campus/jobs) |

## 结构

```
job-pipeline/
├── pipeline/digest.py      # 校验 → 去重 → 过滤过期 → 分组 → 渲染（唯一的功能代码）
├── tests/test_digest.py    # 10 个用例，纯标准库 unittest，无需装包
├── data/jobs.sample.json   # 输入样例：一份真实形态的岗位清单
├── prompt/daily-job-digest.md  # 抓取端提示词：给 AI Agent 用的那部分
└── out/                    # 生成结果（Markdown + HTML 邮件）
```

## 用法

需要 Python 3.10+，无第三方依赖。

```bash
# 生成日报
python -m pipeline.digest data/jobs.sample.json -o out

# 跑测试
python -m unittest discover -s tests -v
```

数据格式（字段少，是为了让抓取端好产出）：

```json
{
  "date": "2026-11-04",
  "scope": ["长沙", "太原", "北京"],
  "jobs": [
    {
      "title": "射频工程师",
      "company": "七十迈（70mai）",
      "city": "上海 / 深圳",
      "track": "通信工程-射频",
      "deadline": "招满即止",
      "url": "https://70mai.zhiye.com/campus/jobs"
    }
  ],
  "no_match_notes": [{"city": "怀化", "note": "地市分公司岗位挂在省公司公告下，不会单独发帖"}],
  "advice": ["国家电网第一批是本周唯一还没开但马上开的窗口"]
}
```

## 几个刻意为之的设计

**「搜不到」不等于「不写」。** 没有任何投递页的岗位，只要写明 `no_url_reason` 就能进日报，渲染时把原因原样印在「投递入口」那一栏。反过来，URL 不是 http(s) 又没有原因的，直接报错整条丢弃——宁可少一条，也不让编造的链接进表格。

**截止日期只认 `YYYY-MM-DD`。** 「招满即止」「以省公司公告为准」这类写法一律不过期，因为没法判断；写死日期的才参与过期过滤。这就避免了两种常见错误：把「招满即止」当过期全删掉，或者写死日期过了还在列表里。

**去重键是「公司 + 岗位名 + 城市」。** 不做模糊匹配：同一家公司同城两个不同岗位（比如「射频工程师」和「测试工程师」）必须都留下。同岗位挂在集团和省公司两处（标题一字不差）才算重复。

**Markdown 与 HTML 分开渲染，不共用一个模板。** Markdown 求可读、能进 git diff；HTML 走邮件，全部内联样式 + table 布局，因为 Gmail 会剥掉 `<style>`，Outlook 不认 flex。

**抓取端不写进代码。** 招聘网站的反爬策略、登录态各不相同，硬编码一堆爬虫既脆弱又有合规风险。这部分交给 `prompt/daily-job-digest.md`——一份让 AI Agent 按规则检索并产出上面那份 JSON 的提示词。想换抓取方式（RSS、官方 API、人工填表）只改提示词，不动代码。

## 测试

```
$ python -m unittest discover -s tests -v
Ran 10 tests in 0.013s
OK
```

覆盖：缺字段报错、非法 URL 无原因报错、有原因放行、去重、同岗位不同城市不算重复、日期型截止过期过滤、自由文本截止不过期、分组顺序、HTML 转义（`<script>` 被转义）、端到端写文件。

其中「有原因放行」这条是**先写测试才发现代码错了**：`url` 原本在必填字段里，导致「搜不到投递页但有说明」的岗位永远进不来，和设计意图相反。

## 已知限制

- 去重是精确匹配，标题差一个字就算两条（日报里会出现近似重复）。真要做模糊去重得引入相似度阈值，收益不抵复杂度。
- 只处理「当天一次」的快照，不做历史岗位追踪。想看某个岗位的开放时间变化，需要自己存历史 JSON 做 diff。
- 日期解析只认 ISO 格式，写「11 月底」这类中文日期不会过期。
- 没有内置发信，`out/*.html` 直接作为邮件正文塞进任意邮件客户端即可（本仓库不保存任何邮箱配置或密钥）。
