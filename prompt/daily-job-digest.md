# 岗位日报 · 抓取端提示词

这份提示词是整条流水线的**上半段**：让 AI Agent 按固定规则检索岗位、产出结构化 JSON。
下半段（校验 / 去重 / 分组 / 渲染）在 `pipeline/digest.py`。

拆成两段的原因：招聘网站的登录态与反爬策略各不相同，硬编码爬虫既脆弱又有合规风险；
而「哪些岗位值得收录、链接必须真实」这类判断，恰恰是模型比正则更擅长的。

## 使用方式

1. 按下面的模板改成你自己的专业、城市、求职方向；
2. 挂到任意支持定时任务的 Agent 上（每天固定时间跑一次）；
3. 让它把结果写成 `data/jobs-YYYY-MM-DD.json`，再执行 `python -m pipeline.digest`。

## 提示词模板

```text
为 <学校> <专业> <毕业年份> 届 <学历> 搜集校招与实习岗位，产出一份结构化 JSON 岗位清单。

## 检索范围
- 目标城市：<城市列表>
- 岗位方向（每类至少 3 条）：
  1) 国企 / 央企：电网、运营商、电科、航天系等
  2) 与专业直接对口的工程技术岗
  3) 相邻方向的技术岗（可迁移技能）
  4) 互联网 / 软件方向（实习与校招均可）
- 时间：优先近 7 天新发布、仍在投递期内的岗位

## 输出格式（严格按此结构，不要额外字段）
{
  "date": "YYYY-MM-DD",
  "scope": ["城市1", "城市2"],
  "jobs": [
    {"title": "岗位名称", "company": "公司", "city": "城市",
     "track": "方向标签", "deadline": "截止说明", "url": "https://..."}
  ],
  "no_match_notes": [{"city": "某城市", "note": "为什么这个城市今天没有匹配岗位"}],
  "advice": ["今日建议 1", "今日建议 2"]
}

## 硬规则
1. url 必须是检索结果里真实出现过的原始页面地址。搜不到确切投递页时，
   url 留空并写 "no_url_reason": "需自行搜索 <公司名>+<岗位名>"，禁止编造或拼接 URL。
2. deadline 能确定具体日期就写 YYYY-MM-DD；只写「招满即止」「以公告为准」这类
   无法判断的说明也可以，程序不会把它当过期。
3. 同一公司 + 同一岗位名 + 同一城市只保留一条，靠前的优先。
4. 只收录与专业背景相关、本科可投的岗位；明确写「硕士起」的可以列，但要在
   advice 里点明门槛，帮助判断精力分配。
5. 某一类当天确实没有岗位，写进 no_match_notes 说明原因，不要用无关岗位凑数。
6. advice 写 3–5 条：哪些最值得投、为什么、投之前要准备什么。要具体到可执行动作，
   不要写「多关注官网」这种空话。
```

## 为什么这几条硬规则值得单独写出来

- **禁止编造 URL**：这是同类工具最常见的翻车点。模型容易把「公司名 + 招聘」拼成一个看起来合理的链接，用户点开是 404，浪费时间还伤信任。
- **允许 `no_url_reason`**：不给出路，模型就会硬凑链接。留一个合法出口，反而更容易拿到真实数据。
- **「硕士起」也照列**：不列出来，用户会以为没机会；列出来并标注门槛，才能把精力错开到真正匹配的岗位上。
- **要求 `no_match_notes`**：某城市没有岗位是常态（地市分公司岗位通常挂在省公司公告下，不单独发帖）。逼模型解释「为什么没有」，比让它沉默有用得多。
